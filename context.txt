1. EXECUTIVE SUMMARY & PROBLEM STATEMENT
--------------------------------------------------------------------------------
Government procurement tenders across India (published via GeM, CPPP, and PSU 
portals) frequently contain ambiguous technical specifications, outdated Indian 
Standards (IS) citations, or omit critical compliance parameters. Manual standards 
verification is slow, prone to compliance errors, and vendor disputes.

StandardIQ is an on-premise, privacy-first AI intelligence engine that:
1. Ingests procurement / tender specifications in plain language.
2. Extracts domain-specific technical requirements and flags ambiguous/missing clauses.
3. Performs semantic retrieval over a curated Bureau of Indian Standards (BIS) corpus.
4. Validates retrieved standards using a deterministic rule engine (checking active 
   vs. superseded editions, QCO orders, and parameter thresholds).
5. Outputs ranked, explainable recommendations backed by source clause evidence.
6. Operates 100% locally with zero data egress — safe for sensitive defense, 
   infrastructure, and government deployments.

2. THE 3-TIER INNOVATION STACK
--------------------------------------------------------------------------------
[Tender Spec / Query]
         │
         ▼
[Tier 1: Local Fine-Tuned LLM (LoRA/QLoRA via Ollama / llama.cpp)]
   - Understands procurement intent and technical jargon.
   - Extracts structured parameters (Voltage, Material, Environment, Application).
   - Flags missing or underspecified clauses (e.g. Missing Operating Temperature).
         │
         ▼
[Tier 2: Hybrid RAG Retrieval (BGE-M3 + ChromaDB / Qdrant)]
   - Holds live BIS standards knowledge base.
   - Encodes specifications into dense vector representations.
   - Retrieves top candidate standards without model retraining.
         │
         ▼
[Tier 3: Rule-Based Guardrail & Verification Engine]
   - Validates active status vs. superseded/withdrawn editions.
   - Checks compliance with mandatory Quality Control Orders (QCO).
   - Verifies technical rating mismatches (e.g., 750V vs 1.1kV).
         │
         ▼
[Confidence Scoring & Routing]
   ├── High (>= 80%): Recommended with source evidence and compliance badges.
   ├── Moderate (50-80%): Flagged with specific mismatch warnings for buyer review.
   └── Low (< 50%) / Superseded: Flagged as invalid/superseded; routed to human review.

6. TECHNICAL ROADMAP (PHASE 2 & FULL SYSTEM INTEGRATION)
--------------------------------------------------------------------------------
When expanding this project into a full backend + model deployment:
1. Backend Service (FastAPI):
   - Scaffold `backend/` directory with `app/main.py`.
   - Endpoints:
     * POST `/api/v1/extract-requirements`: Runs local LLM prompt template to parse specs.
     * POST `/api/v1/recommend-standards`: Runs vector similarity + rule validation.
     * POST `/api/v1/upload-tender-pdf`: Parses tender PDF via PyMuPDF (`fitz`).
2. Local Model Serving:
   - Serve open-weight model (e.g. Qwen2.5-7B-Instruct or Llama-3.2-3B fine-tuned with 
     Unsloth / LoRA on procurement specs) via Ollama (`http://localhost:11434`) or vLLM.
3. Vector Retrieval & Indexing:
   - Use `sentence-transformers` with `BAAI/bge-m3` for multilingual & dense embeddings.
   - Store 200-500 curated BIS standard abstracts in ChromaDB or Qdrant.
4. Rule Engine Implementation:
   - Python module `engine/rules.py` with deterministic validation rules:
     * Status validator: Cross-references standard number against live BIS Gazette active/withdrawn table.
     * QCO validator: Verifies mandatory ISI mark requirements under Ministry notifications.
     * Threshold validator: Compares numerical attributes (voltage, grade, temp) against extracted limits.
5. Knowledge Graph (Phase 2):
   - Neo4j graph tracking standard supersession chains, cross-references (e.g. IS 456 references IS 1489), 
     and sector taxonomy.
